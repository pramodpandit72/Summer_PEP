# Backend Architecture

## What is Backend?

The backend is the part of an application that users cannot see. It handles business logic, stores data, processes requests, and sends responses to the frontend.

### Example

When a user logs into a website:

1. The frontend sends the username and password.
2. The backend checks the database.
3. If the details are correct, the backend sends a success response.
4. Otherwise, it sends an error message.

---

## Components of Backend Architecture

### 1. Client

The client is the application used by the user.

Examples:
- Web Browser
- Mobile App
- Desktop Application

---

### 2. Server

The server receives requests from the client, processes them, and returns responses.

Example:
- Node.js
- Express.js

---

### 3. Database

The database stores application data.

Examples:
- MySQL
- PostgreSQL
- MongoDB

---

### 4. API

API (Application Programming Interface) allows the frontend and backend to communicate.

Example:

Frontend requests:

```
GET /users
```

Backend returns:

```json
[
  {
    "id": 1,
    "name": "Rahul"
  }
]
```

# REST Principles

## What is REST?

REST stands for **Representational State Transfer**.

It is a set of rules for designing web APIs that allows communication between the client and server using HTTP.

---

## Features of REST

- Client and server are separate.
- Uses HTTP methods.
- Resources are identified using URLs.
- Responses are usually in JSON format.
- Easy to understand and scalable.

---

## REST Architecture

```
Client
   |
HTTP Request
   |
   v
REST API
   |
Business Logic
   |
Database
   |
HTTP Response (JSON)
```

---

## REST Resource

A resource is any object or data.

Examples

```
/users
/products
/orders
/books
```

---

## HTTP Methods

### GET

Used to retrieve data.

Example

```
GET /users
```

---

### POST

Used to create new data.

Example

```
POST /users
```

---

### PUT

Used to update the entire resource.

Example

```
PUT /users/1
```

---

### PATCH

Used to update only specific fields.

Example

```
PATCH /users/1
```

---

### DELETE

Used to remove data.

Example

```
DELETE /users/1
```

---

## HTTP Status Codes

### 200 OK

Request completed successfully.

---

### 201 Created

New resource created successfully.

---

### 400 Bad Request

Client sent an invalid request.

---

### 401 Unauthorized

Authentication is required.

---

### 403 Forbidden

User is authenticated but does not have permission.

---

### 404 Not Found

Requested resource does not exist.

---

### 500 Internal Server Error

Something went wrong on the server.

---

## REST Constraints

### 1. Client-Server

Frontend and backend work independently.

---

### 2. Stateless

The server does not remember previous requests.

Each request must contain all required information.

---

### 3. Cacheable

Responses can be cached to improve performance.

---

### 4. Uniform Interface

APIs should follow a consistent structure.

Example

```
GET /users
POST /users
GET /users/1
DELETE /users/1
```

---

### 5. Layered System

The client does not know whether it is connected directly to the server or through another service.

# Node.js Runtime

## What is Node.js?

Node.js is a JavaScript runtime environment that allows JavaScript code to run outside the browser.

It is mainly used for backend development.

---

## Why Node.js?

- Fast execution
- Uses JavaScript for frontend and backend
- Handles many users simultaneously
- Large package ecosystem (NPM)
- Easy to build APIs

---

## How Node.js Works

```
User Request
      |
      v
Node.js
      |
Event Loop
      |
Non-blocking Operations
      |
Database/File/API
      |
Response
```

---

## Features of Node.js

- Asynchronous
- Event-driven
- Non-blocking I/O
- Single-threaded
- Fast execution using Google's V8 Engine
- Cross-platform

---

## V8 Engine

V8 is Google's JavaScript engine.

It converts JavaScript code into machine code for faster execution.

---

## Event Loop

The Event Loop continuously checks whether asynchronous tasks are complete.

If a task is completed, it moves the callback to the execution queue.

This allows Node.js to handle multiple requests efficiently.

---

## Blocking vs Non-Blocking

### Blocking

The program waits until the current task finishes.

Example:

```
Read File
Wait
Next Task
```

---

### Non-Blocking

The program starts the task and continues executing other tasks.

Example:

```
Read File
Do Other Work
File Completed
Return Result
```

---

## Asynchronous Programming

Instead of waiting for one task to finish, Node.js performs other work.

Example:

```javascript
console.log("Start");

setTimeout(() => {
    console.log("Done");
}, 2000);

console.log("End");
```

Output

```
Start
End
Done
```

---

## NPM

NPM stands for **Node Package Manager**.

It is used to install and manage packages.

Example

```
npm install express
```

# Important Questions with Answers

## Q1. What is backend development?

**Answer:**
Backend development is the server-side part of an application. It processes requests, manages databases, applies business logic, and sends responses to the client.

---

## Q2. What is backend architecture?

**Answer:**
Backend architecture is the structure of backend components such as the server, database, APIs, and business logic that work together to process client requests.

---

## Q3. What is REST?

**Answer:**
REST (Representational State Transfer) is a set of architectural principles used to design web APIs that communicate using HTTP.

---

## Q4. What are the common HTTP methods?

**Answer:**

- GET – Retrieve data
- POST – Create data
- PUT – Update entire resource
- PATCH – Update part of a resource
- DELETE – Remove data

---

## Q5. What is a REST API?

**Answer:**
A REST API is an API that follows REST principles and uses HTTP methods to access and manipulate resources.

---

## Q6. What is a resource in REST?

**Answer:**
A resource is any data object that can be accessed through a URL, such as `/users` or `/products`.

---

## Q7. What does stateless mean?

**Answer:**
Stateless means the server does not store client information between requests. Every request must contain all necessary information.

---

## Q8. What is Node.js?

**Answer:**
Node.js is a JavaScript runtime environment that allows JavaScript to run on the server.

---

## Q9. Why is Node.js fast?

**Answer:**
Node.js is fast because it uses the V8 Engine, non-blocking I/O, asynchronous programming, and an event-driven architecture.

---

## Q10. What is the Event Loop?

**Answer:**
The Event Loop manages asynchronous operations by continuously checking whether tasks are complete and executing their callbacks.

---

## Q11. What is non-blocking I/O?

**Answer:**
Non-blocking I/O allows Node.js to continue executing other tasks while waiting for operations like file reading or database queries to complete.

---

## Q12. What is NPM?

**Answer:**
NPM (Node Package Manager) is the default package manager for Node.js used to install, update, and manage libraries and dependencies.

---

## Q13. What is the difference between PUT and PATCH?

**Answer:**

- PUT updates the entire resource.
- PATCH updates only the specified fields.

---

## Q14. What is the role of an API?

**Answer:**
An API enables communication between the frontend and backend by allowing clients to send requests and receive responses.

---

## Q15. Name three databases commonly used with Node.js.

- MongoDB
