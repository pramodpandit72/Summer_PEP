# Express.js Advanced Routing and Middleware

---

# What is Express.js?

Express.js is a lightweight and fast web framework for Node.js. It helps developers build web applications and REST APIs easily by providing routing, middleware, and request handling features.

---

# What is Routing?

Routing is the process of deciding how an application responds to a client's request for a specific URL and HTTP method.

A route consists of:

- HTTP Method (GET, POST, PUT, DELETE, etc.)
- URL (Path)
- Callback Function (Handler)

Example:

```javascript
app.get('/home', (req, res) => {
    res.send('Welcome to Home Page');
});
```

When a client sends a **GET** request to `/home`, the server responds with **"Welcome to Home Page"**.

---

# Route Parameters

Route parameters allow dynamic values in the URL.

Example:

```javascript
app.get('/users/:id', (req, res) => {
    res.send(req.params.id);
});
```

Request:

```
GET /users/101
```

Output:

```
101
```

`req.params` contains all route parameters.

---

# Query Parameters

Query parameters are used to send optional data in the URL.

Example:

```javascript
app.get('/search', (req, res) => {
    res.send(req.query.name);
});
```

Request:

```
GET /search?name=Rahul
```

Output:

```
Rahul
```

`req.query` contains all query parameters.

---

# Route Chaining

Multiple handlers can be attached to the same route.

Example:

```javascript
app.route('/users')
    .get((req, res) => {
        res.send('Get Users');
    })
    .post((req, res) => {
        res.send('Create User');
    });
```

Benefits:

- Cleaner code
- Better organization
- Avoids repeating the same route path

---

# Express Router

Express Router is used to organize routes into separate files.

Example:

```javascript
const express = require('express');
const router = express.Router();

router.get('/', (req, res) => {
    res.send('Users Route');
});

module.exports = router;
```

Main file:

```javascript
const userRoutes = require('./routes/users');

app.use('/users', userRoutes);
```

Benefits:

- Modular code
- Easy maintenance
- Better project structure

---

# Nested Routes

Nested routes represent relationships between resources.

Example:

```
/users/1/orders
```

This means:

- User ID = 1
- Get all orders of that user

---

# Wildcard Route

A wildcard route handles requests that do not match any defined route.

Example:

```javascript
app.get('*', (req, res) => {
    res.status(404).send('Page Not Found');
});
```

---

# What is Middleware?

Middleware is a function that runs between the client's request and the server's response.

It can:

- Execute code
- Modify request and response objects
- Validate data
- Authenticate users
- Log requests
- End the request-response cycle
- Pass control to the next middleware

---

# Middleware Flow

```
Client Request
      |
      v
Middleware 1
      |
      v
Middleware 2
      |
      v
Route Handler
      |
      v
Response
```

---

# Middleware Function Syntax

```javascript
function middleware(req, res, next) {
    console.log("Middleware Executed");
    next();
}
```

- `req` → Request object
- `res` → Response object
- `next()` → Passes control to the next middleware

---

# Types of Middleware

## 1. Application-Level Middleware

Applied to the entire application.

Example:

```javascript
app.use((req, res, next) => {
    console.log("Request Received");
    next();
});
```

Runs for every request.

---

## 2. Route-Level Middleware

Applied only to specific routes.

Example:

```javascript
function checkUser(req, res, next) {
    console.log("Checking User");
    next();
}

app.get('/profile', checkUser, (req, res) => {
    res.send('Profile');
});
```

Runs only for the `/profile` route.

---

## 3. Built-in Middleware

Express provides built-in middleware.

### JSON Middleware

```javascript
app.use(express.json());
```

Converts incoming JSON data into JavaScript objects.

---

### URL Encoded Middleware

```javascript
app.use(express.urlencoded({ extended: true }));
```

Reads form data submitted by HTML forms.

---

## 4. Error-Handling Middleware

Used to handle application errors.

Syntax:

```javascript
app.use((err, req, res, next) => {
    res.status(500).send("Something Went Wrong");
});
```

Error-handling middleware has four parameters:

- err
- req
- res
- next

---

## 5. Third-Party Middleware

Middleware created by other developers.

Common Examples:

- Morgan (Logging)
- CORS (Cross-Origin Resource Sharing)
- Helmet (Security)
- Compression (Response Compression)

Example:

```javascript
const cors = require('cors');

app.use(cors());
```

---

# Middleware Execution Order

Middleware runs in the same order it is written.

Example:

```javascript
app.use((req, res, next) => {
    console.log("First");
    next();
});

app.use((req, res, next) => {
    console.log("Second");
    next();
});

app.get('/', (req, res) => {
    res.send("Home");
});
```

Output:

```
First
Second
Home
```

---

# next() Function

`next()` passes control to the next middleware or route handler.

Example:

```javascript
app.use((req, res, next) => {
    console.log("Middleware");
    next();
});

app.get('/', (req, res) => {
    res.send("Success");
});
```

Without `next()`, the request will stop and the client may not receive a response.

---

# Request Object (req)

The request object contains information sent by the client.

Common Properties:

- req.params
- req.query
- req.body
- req.headers
- req.method
- req.url

---

# Response Object (res)

The response object is used to send data back to the client.

Common Methods:

```javascript
res.send();
res.json();
res.status();
res.redirect();
res.download();
```

Example:

```javascript
res.status(200).json({
    message: "Success"
});
```

---

# Common Middleware Use Cases

- Authentication
- Authorization
- Logging
- Data Validation
- Error Handling
- Parsing JSON
- Security
- File Upload

---

# Best Practices

- Keep middleware small and focused.
- Always call `next()` unless sending a response.
- Use Express Router for large projects.
- Handle errors using error-handling middleware.
- Organize routes into separate files.
- Use built-in and third-party middleware when needed.

---

# Summary

## Express.js Routing

- Maps URLs to functions.
- Supports route parameters and query parameters.
- Uses Express Router for modular routing.
- Supports route chaining and nested routes.

---

## Middleware

- Executes between request and response.
- Can modify requests and responses.
- Used for authentication, logging, validation, and error handling.
- Runs in the order it is defined.
- Uses `next()` to continue the request lifecycle.

# Important Questions with Answers

## Q1. What is Express.js?

**Answer:**
Express.js is a fast and lightweight web framework for Node.js used to build web applications and REST APIs.

---

## Q2. What is routing in Express.js?

**Answer:**
Routing is the process of handling client requests based on the URL and HTTP method, then sending the appropriate response.

---

## Q3. What is a route parameter?

**Answer:**
A route parameter is a dynamic value in the URL used to identify a specific resource, such as `/users/:id`.

---

## Q4. What is the difference between route parameters and query parameters?

**Answer:**

- Route parameters are part of the URL path (e.g., `/users/10`).
- Query parameters are optional values added after `?` (e.g., `/search?name=Rahul`).

---

## Q5. What is Express Router?

**Answer:**
Express Router is a mini router that helps organize application routes into separate files, making the project modular and easier to maintain.

---

## Q6. What is middleware?

**Answer:**
Middleware is a function that executes between the client's request and the server's response. It can process requests, validate data, authenticate users, and more.

---

## Q7. What is the purpose of `next()` in middleware?

**Answer:**
`next()` passes control to the next middleware or route handler. Without it, the request processing stops unless a response is sent.

---

## Q8. Name the types of middleware in Express.js.

**Answer:**

- Application-Level Middleware
- Route-Level Middleware
- Built-in Middleware
- Error-Handling Middleware
- Third-Party Middleware

---

## Q9. What is the use of `express.json()`?

**Answer:**
`express.json()` is built-in middleware that converts incoming JSON request data into JavaScript objects.

---

## Q10. What is error-handling middleware?

**Answer:**
Error-handling middleware catches application errors and sends an appropriate response to the client. It has four parameters: `err`, `req`, `res`, and `next`.

---

## Q11. In what order does Express execute middleware?

**Answer:**
Express executes middleware in the same order in which they are defined in the application.

---

## Q12. What is the difference between `req.params` and `req.query`?

**Answer:**

- `req.params` stores route parameters from the URL path.
- `req.query` stores query string values from the URL.

- Data Validation
- Error Handling
- Parsing JSON
- Security
- File Upload

## Q14. What is route chaining?

**Answer:**
Route chaining allows multiple HTTP methods (GET, POST, PUT, etc.) to be defined for the same route using `app.route()`.

**Answer:**
Express Router keeps routes organized, improves code readability, supports modular development, and makes the application easier to maintain.
