# Authentication, JWT, OAuth2, and RBAC

---

# Authentication

## What is Authentication?

Authentication is the process of verifying the identity of a user.

It answers the question:

**"Who are you?"**

A user must prove their identity before accessing protected resources.

Common methods of authentication:

- Username and Password
- OTP (One-Time Password)
- Fingerprint
- Face Recognition
- JWT Token
- OAuth Login (Google, GitHub, Facebook)

---

## Authentication Process

```
User
   |
Enter Username & Password
   |
   v
Server
   |
Verify Credentials
   |
   +---- Valid -----> Login Successful
   |
   +---- Invalid ---> Access Denied
```

---

## Authentication vs Authorization

| Authentication | Authorization |
|---------------|---------------|
| Verifies the user's identity | Verifies what the user is allowed to access |
| Happens first | Happens after authentication |
| Checks "Who are you?" | Checks "What can you do?" |

Example:

- Login with email and password → Authentication
- Access the Admin Dashboard → Authorization

---

# Session-Based Authentication

In session-based authentication:

1. User logs in.
2. Server verifies credentials.
3. Server creates a session.
4. Session ID is stored in the browser (usually as a cookie).
5. Every request sends the session ID.
6. Server checks the session before allowing access.

---

## Advantages

- Easy to implement
- Server controls user sessions

## Disadvantages

- Server must store session data
- Difficult to scale for large applications

---

# Token-Based Authentication

Instead of storing sessions, the server creates a token after successful login.

The client stores the token and sends it with every request.

Example:

```
Authorization: Bearer <token>
```

The server verifies the token before processing the request.

---

# JSON Web Token (JWT)

## What is JWT?

JWT (JSON Web Token) is a secure token used for authentication and authorization.

It allows users to access protected resources without storing session data on the server.

JWT is compact, secure, and widely used in REST APIs.

---

## Structure of JWT

A JWT has three parts:

```
Header.Payload.Signature
```

Example:

```
xxxxx.yyyyy.zzzzz
```

---

### 1. Header

Contains information about the token.

Example:

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

---

### 2. Payload

Contains user information (claims).

Example:

```json
{
  "id": 1,
  "name": "Rahul",
  "role": "Admin"
}
```

Do **not** store sensitive information such as passwords in the payload.

---

### 3. Signature

Used to verify that the token has not been modified.

The server creates the signature using a secret key.

---

## JWT Authentication Flow

```
User Login
      |
      v
Server Verifies User
      |
      v
JWT Generated
      |
      v
Client Stores JWT
      |
      v
Client Sends JWT
      |
      v
Server Verifies JWT
      |
      v
Protected Resource
```

---

## Advantages of JWT

- Stateless
- Fast authentication
- Easy to use with REST APIs
- Works well in distributed systems
- Can be used across different platforms

---

## Disadvantages of JWT

- Cannot be easily revoked before expiration
- Token size is larger than a session ID
- If a token is stolen, it can be misused until it expires

---

# OAuth 2.0

## What is OAuth 2.0?

OAuth 2.0 is an authorization framework that allows users to grant an application limited access to their data without sharing their password.

It is commonly used for **"Login with Google"**, **"Login with GitHub"**, and **"Login with Facebook"**.

---

## Why OAuth 2.0?

Without OAuth:

- User shares their password with every application.

With OAuth:

- User logs in through a trusted provider.
- The application receives an access token instead of the user's password.

---

## OAuth 2.0 Roles

### 1. Resource Owner

The user who owns the data.

Example:

You

---

### 2. Client

The application requesting access.

Example:

A shopping website using Google Login.

---

### 3. Authorization Server

The server that verifies the user's identity and issues access tokens.

Example:

Google Login Server

---

### 4. Resource Server

The server that stores user data.

Example:

Google APIs

---

## OAuth 2.0 Flow

```
User
   |
Login with Google
   |
   v
Authorization Server
   |
User Grants Permission
   |
   v
Access Token Issued
   |
   v
Application
   |
   v
Resource Server
```

---

## Access Token

An access token is issued after successful authorization.

It is sent with API requests.

Example:

```
Authorization: Bearer ACCESS_TOKEN
```

---

## Refresh Token

A refresh token is used to obtain a new access token after the current one expires.

Benefits:

- User does not need to log in again.
- Improves user experience.
- Increases security by using short-lived access tokens.

---

## Advantages of OAuth 2.0

- User passwords are not shared.
- Secure authorization.
- Supports third-party login.
- Widely adopted by major platforms.
- Improves user experience.

---

# Role-Based Access Control (RBAC)

## What is RBAC?

RBAC (Role-Based Access Control) is an authorization model where permissions are assigned based on user roles.

Instead of giving permissions to each user individually, permissions are assigned to roles.

---

## Common Roles

- Admin
- Manager
- Teacher
- Student
- Customer

---

## Example

| Role | Permission |
|------|------------|
| Admin | Read, Create, Update, Delete |
| Teacher | Read, Create, Update |
| Student | Read Only |

---

## RBAC Flow

```
User Login
      |
Authentication
      |
User Role
      |
Permission Check
      |
Access Allowed or Denied
```

---

## RBAC Example in Express

```javascript
function checkAdmin(req, res, next) {
    if (req.user.role === "Admin") {
        next();
    } else {
        res.status(403).send("Access Denied");
    }
}
```

Only users with the **Admin** role can access the protected route.

---

## Advantages of RBAC

- Easy to manage permissions
- Improves security
- Reduces duplicate permission settings
- Scales well for large applications

---

## Authentication + JWT + RBAC Flow

```
User Login
      |
      v
Authentication
      |
      v
JWT Generated
      |
      v
Client Sends JWT
      |
      v
Server Verifies JWT
      |
      v
Check User Role (RBAC)
      |
      +---- Authorized ----> Access Granted
      |
      +---- Unauthorized --> Access Denied
```

---

# Best Practices

- Store passwords in hashed form (e.g., bcrypt).
- Never store passwords inside JWT payloads.
- Use HTTPS to protect tokens during transmission.
- Set expiration time for JWTs.
- Use refresh tokens for long-lived sessions.
- Apply RBAC to protect sensitive routes.
- Validate and verify every JWT before granting access.

# Important Questions with Answers

## Q1. What is authentication?

**Answer:**
Authentication is the process of verifying a user's identity before allowing access to an application or system.

---

## Q2. What is the difference between authentication and authorization?

**Answer:**

- Authentication verifies **who the user is**.
- Authorization determines **what the user is allowed to access**.

---

## Q3. What is JWT?

**Answer:**
JWT (JSON Web Token) is a secure token used for authentication and authorization. It allows clients to access protected resources without storing session data on the server.

---

## Q4. What are the three parts of a JWT?

**Answer:**

1. Header
2. Payload
3. Signature

---

## Q5. What is stored in the JWT payload?

**Answer:**
The payload contains user information (claims), such as user ID or role. Sensitive data like passwords should never be stored in the payload.

---

## Q6. Why is JWT called stateless?

**Answer:**
JWT is called stateless because the server does not store session information. The client sends the token with each request.

---

## Q7. What is OAuth 2.0?

**Answer:**
OAuth 2.0 is an authorization framework that allows users to grant applications limited access to their data without sharing their passwords.

---

## Q8. What is an access token?

**Answer:**
An access token is a credential issued after successful authorization. It is used to access protected resources.

---

## Q9. What is a refresh token?

**Answer:**
A refresh token is used to obtain a new access token when the current access token expires, without requiring the user to log in again.

---

## Q10. What is RBAC?

**Answer:**
RBAC (Role-Based Access Control) is an authorization model where permissions are assigned based on user roles.

---

## Q11. Give examples of user roles in RBAC.

**Answer:**

- Admin
- Manager
- Teacher
- Student
- Customer

---

## Q12. Why is RBAC important?

**Answer:**
RBAC improves security, simplifies permission management, and ensures users can access only the resources allowed for their roles.

---

## Q13. What is the difference between session-based and token-based authentication?

**Answer:**

- Session-based authentication stores session data on the server.
- Token-based authentication uses tokens (such as JWT) and does not require server-side session storage.

---

## Q14. Why should HTTPS be used with JWT?

**Answer:**
HTTPS encrypts data during transmission, protecting JWTs from being intercepted by attackers.

---

## Q15. Why should passwords never be stored in a JWT?

**Answer:**
JWT payloads can be decoded, so storing passwords or other sensitive information in them is a serious security risk.
