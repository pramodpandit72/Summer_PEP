# MongoDB Advanced Data Modeling

---

# What is Data Modeling?

Data modeling is the process of designing how data is stored, organized, and related in a database.

A good data model helps to:

- Store data efficiently
- Improve query performance
- Reduce duplicate data
- Make applications easier to maintain

---

# What is MongoDB Data Modeling?

MongoDB stores data in **documents** instead of rows and columns.

Each document is stored in a **collection** and uses **JSON-like BSON format**.

Example:

```json
{
    "_id": 1,
    "name": "Rahul",
    "age": 20,
    "city": "Delhi"
}
```

---

# Goals of Data Modeling

- Improve performance
- Reduce unnecessary database queries
- Support application requirements
- Keep data organized
- Allow future scalability

---

# Embedding vs Referencing

MongoDB provides two main ways to store related data.

1. Embedding
2. Referencing

---

# Embedding (Embedded Documents)

In embedding, related data is stored inside the same document.

Example:

```json
{
    "_id": 1,
    "name": "Rahul",
    "orders": [
        {
            "product": "Laptop",
            "price": 50000
        },
        {
            "product": "Mouse",
            "price": 800
        }
    ]
}
```

Everything is stored in one document.

---

## Advantages of Embedding

- Faster data retrieval
- Fewer database queries
- Simple document structure
- Good for one-to-one and one-to-few relationships

---

## Disadvantages of Embedding

- Document size can become very large
- Duplicate data may occur
- Updating embedded data may be difficult

---

# Referencing

In referencing, related data is stored in separate collections and linked using document IDs.

Users Collection

```json
{
    "_id": 1,
    "name": "Rahul"
}
```

Orders Collection

```json
{
    "_id": 101,
    "userId": 1,
    "product": "Laptop"
}
```

The `userId` connects the order to the user.

---

## Advantages of Referencing

- Reduces duplicate data
- Better for large datasets
- Easier to update related data
- Suitable for one-to-many and many-to-many relationships

---

## Disadvantages of Referencing

- Requires multiple queries or aggregation
- Slightly slower than embedding

---

# Embedding vs Referencing

| Embedding | Referencing |
|-----------|-------------|
| Stores related data in one document | Stores related data in separate collections |
| Faster reads | Better for large datasets |
| Fewer queries | More flexible |
| Can increase document size | Requires joining related data |

---

# One-to-One Relationship

One document is related to only one other document.

Example:

A user has one profile.

```json
{
    "name": "Rahul",
    "profile": {
        "phone": "9876543210",
        "city": "Delhi"
    }
}
```

Embedding is usually the best choice.

---

# One-to-Many Relationship

One document is related to many documents.

Example:

One customer has many orders.

```json
Customer
{
    "_id": 1,
    "name": "Rahul"
}
```

```json
Order
{
    "customerId": 1,
    "product": "Laptop"
}
```

Referencing is preferred when the number of related documents is large.

---

# Many-to-Many Relationship

Many documents are related to many other documents.

Example:

Students and Courses.

A student can enroll in many courses, and a course can have many students.

Student

```json
{
    "_id": 1,
    "name": "Rahul"
}
```

Course

```json
{
    "_id": 101,
    "title": "Full Stack Development"
}
```

Enrollment

```json
{
    "studentId": 1,
    "courseId": 101
}
```

This is usually implemented using references.

---

# Schema Design Patterns

MongoDB supports different schema design patterns.

---

## 1. Embedded Pattern

Stores related data in the same document.

Best for:

- User profile
- Address
- Product specifications

---

## 2. Reference Pattern

Stores related data separately.

Best for:

- Orders
- Products
- Students
- Employees

---

## 3. Bucket Pattern

Groups similar data into one document.

Example:

Store daily temperature readings together instead of creating one document for each reading.

Benefits:

- Fewer documents
- Better performance for time-series data

---

## 4. Computed Pattern

Stores calculated values instead of calculating them every time.

Example:

```json
{
    "product": "Laptop",
    "totalSales": 250
}
```

Benefits:

- Faster queries
- Less repeated calculation

---

# Denormalization

Denormalization means storing duplicate data to improve read performance.

Example:

Instead of looking up the user's name every time, store it inside the order document.

```json
{
    "product": "Laptop",
    "customerName": "Rahul"
}
```

Benefits:

- Faster data retrieval
- Fewer database queries

Disadvantage:

- Duplicate data must be updated in multiple places.

---

# Normalization

Normalization means storing data in separate collections to reduce duplication.

Example:

Users Collection

```json
{
    "_id": 1,
    "name": "Rahul"
}
```

Orders Collection

```json
{
    "userId": 1,
    "product": "Laptop"
}
```

Benefits:

- Less duplicate data
- Easier updates
- Better data consistency

---

# Indexing and Data Modeling

Indexes improve query performance.

Example:

```javascript
db.users.createIndex({ email: 1 });
```

Benefits:

- Faster searches
- Faster sorting
- Faster filtering

---

# Data Validation

MongoDB allows validation rules to ensure correct data is stored.

Example:

```json
{
    "name": "Rahul",
    "age": 20
}
```

Validation Rules:

- Name must be a string.
- Age must be a number.
- Email must be unique.

---

# Best Practices for Data Modeling

- Choose embedding for small related data.
- Choose referencing for large related data.
- Avoid unnecessary duplicate data.
- Keep documents reasonably small.
- Create indexes for frequently searched fields.
- Design the schema based on application queries.
- Use validation to maintain data quality.

# Important Questions with Answers

## Q1. What is data modeling in MongoDB?

**Answer:**
Data modeling is the process of designing how data is stored, organized, and related in MongoDB collections and documents.

---

## Q2. What are the two main data modeling approaches in MongoDB?

**Answer:**

- Embedding
- Referencing

---

## Q3. What is embedding?

**Answer:**
Embedding stores related data inside the same document. It is suitable for one-to-one and one-to-few relationships.

---

## Q4. What is referencing?

**Answer:**
Referencing stores related data in separate collections and connects them using document IDs. It is suitable for one-to-many and many-to-many relationships.

---

## Q5. What is the difference between embedding and referencing?

**Answer:**

- Embedding stores related data in one document and provides faster reads.
- Referencing stores related data in separate collections, reducing duplication and improving flexibility.

---

## Q6. When should you use embedding?

**Answer:**
Use embedding when related data is small, frequently accessed together, and does not change often.

---

## Q7. When should you use referencing?

**Answer:**
Use referencing when related data is large, changes frequently, or is shared by multiple documents.

---

## Q8. What is normalization?

**Answer:**
Normalization stores data in separate collections to reduce duplicate data and improve consistency.

---

## Q9. What is denormalization?

**Answer:**
Denormalization stores some duplicate data to improve read performance and reduce database queries.

---

## Q10. What is the Bucket Pattern?

**Answer:**
The Bucket Pattern groups similar data into a single document, making it useful for time-series data.

---

## Q11. What is the Computed Pattern?

**Answer:**
The Computed Pattern stores calculated values, such as totals or averages, to avoid recalculating them repeatedly.

---

## Q12. Why are indexes important in MongoDB?

**Answer:**
Indexes improve query performance by making searches, sorting, and filtering faster.

---

## Q13. What is a one-to-many relationship?

**Answer:**
A one-to-many relationship exists when one document is related to multiple documents, such as one customer having many orders.

---

## Q14. What is a many-to-many relationship?

**Answer:**
A many-to-many relationship exists when multiple documents are related to multiple other documents, such as students enrolling in many courses.

---

## Q15. What are the best practices for MongoDB data modeling?

**Answer:**

- Use embedding for small related data.
- Use referencing for large related data.
- Keep documents reasonably small.
- Avoid unnecessary duplication.
- Create indexes on frequently queried fields.
- Design the schema based on application needs.
- Apply validation rules to ensure data quality.
