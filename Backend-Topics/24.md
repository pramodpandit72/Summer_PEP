# Microservices Architecture

---

# What is Microservices Architecture?

Microservices Architecture is a software design approach where an application is divided into **small, independent services**.

Each service:

- Performs one specific business function.
- Has its own codebase.
- Can be developed, deployed, and maintained independently.
- Communicates with other services through APIs.

Example:

An E-commerce application can be divided into:

- User Service
- Product Service
- Order Service
- Payment Service
- Notification Service

Each service works independently.

---

# Why Use Microservices?

As applications grow, managing a single large application becomes difficult.

Microservices solve this problem by breaking the application into smaller services.

Benefits include:

- Easier development
- Independent deployment
- Better scalability
- Improved maintainability
- Fault isolation

---

# Monolithic Architecture vs Microservices Architecture

| Monolithic Architecture | Microservices Architecture |
|--------------------------|---------------------------|
| Single large application | Multiple small services |
| One codebase | Separate codebase for each service |
| Entire application is deployed together | Each service is deployed independently |
| Difficult to scale specific features | Easy to scale individual services |
| Failure in one module can affect the whole application | Failure in one service usually does not stop other services |

# Components of Microservices Architecture

## 1. Client

The client sends requests.

Examples:

- Web Browser
- Mobile App
- Desktop Application

---

## 2. API Gateway

The API Gateway is the entry point for all client requests.

Responsibilities:

- Receives requests
- Routes requests to the correct service
- Handles authentication
- Performs rate limiting
- Aggregates responses if needed

---

## 3. Microservices

Each microservice handles one business function.

Examples:

- User Service
- Product Service
- Inventory Service
- Order Service
- Payment Service

---

## 4. Database

Each microservice should have its own database.

Example:

```
User Service
    |
User Database

Order Service
    |
Order Database
```

This reduces dependency between services.

# Service Communication

Microservices communicate with each other using APIs or messaging systems.

### Synchronous Communication

The client waits for the response.

Example:

- REST API
- HTTP

```
Order Service
      |
      v
Payment Service
      |
      v
Response
```

---

### Asynchronous Communication

The sender does not wait for an immediate response.

Common Message Brokers:

- RabbitMQ
- Apache Kafka

```
Order Service
      |
      v
Message Queue
      |
      v
Notification Service
```

---

# REST API in Microservices

Most microservices communicate using REST APIs.

Example:

```
GET /users

POST /orders

PUT /products/10

DELETE /orders/5
```

REST makes communication simple and platform-independent.

---

# Database per Service

Each service owns its data.

Example:

```
User Service
     |
User Database

Order Service
     |
Order Database

Payment Service
     |
Payment Database
```

Advantages:

- Independent updates
- Better scalability
- Improved security
- Reduced coupling

- Independent development

- Easy scalability
- Better fault isolation

# API Gateway

## What is an API Gateway?

An API Gateway is a server that acts as the single entry point for all client requests.

Functions:

- Request routing
- Authentication
- Authorization
- Rate limiting
- Load balancing
- Response aggregation

Example:

```
Client
   |
API Gateway
   |
--------------------------
|      |       |         |
User  Order  Product  Payment
```

---

# Load Balancing

Load balancing distributes requests across multiple instances of a service.

Example:

```
Client
   |
Load Balancer
   |
-------------------
|        |        |
Server1 Server2 Server3
```

Benefits:

- Better performance
- High availability
- Prevents server overload

---

# Scalability

Scalability means increasing the application's capacity to handle more users.

Example:

If the Product Service receives heavy traffic, only that service can be scaled.

```
Product Service

Server 1
Server 2
Server 3
```

Other services remain unchanged.

---

# Fault Tolerance

Fault tolerance means the application continues to work even if one service fails.

Example:

If the Notification Service stops working:

- Orders can still be placed.
- Payments can still be processed.

Only notifications are affected.

---

# Monitoring

Monitoring helps track the health and performance of services.

Common monitoring tasks:

- CPU usage
- Memory usage
- Response time
- Error rates
- Service availability

Popular tools:

- Prometheus
- Grafana

---

# Logging

Each service should maintain its own logs.

Logs help in:

- Debugging
- Error tracking
- Performance analysis

---

# Best Practices

- Design services around a single business function.
- Keep services loosely coupled.
- Give each service its own database.
- Use API Gateway for client communication.
- Secure APIs with authentication and authorization.
- Monitor services regularly.
- Use centralized logging.
- Automate deployment using CI/CD.
- Use asynchronous communication when appropriate.

# Important Questions with Answers

## Q1. What is Microservices Architecture?

**Answer:**
Microservices Architecture is a software design approach in which an application is divided into small, independent services, each responsible for a specific business function.

---

## Q2. What are the main characteristics of microservices?

**Answer:**

- Small and independent
- Loosely coupled
- Highly scalable
- Independently deployable
- Fault tolerant
- Easy to maintain

---

## Q3. What is the difference between Monolithic and Microservices Architecture?

**Answer:**

- Monolithic architecture has a single codebase and is deployed as one application.
- Microservices architecture consists of multiple independent services that can be deployed and scaled separately.

---

## Q4. Why does each microservice have its own database?

**Answer:**
Each microservice owns its data, reducing dependencies between services and allowing independent development, deployment, and scaling.

---

## Q5. What is an API Gateway?

**Answer:**
An API Gateway is the single entry point for client requests. It routes requests to the appropriate microservice and can also handle authentication, authorization, and rate limiting.

---

## Q6. How do microservices communicate?

**Answer:**
Microservices communicate through REST APIs (synchronous communication) or messaging systems such as RabbitMQ and Apache Kafka (asynchronous communication).

---

## Q7. What is synchronous communication?

**Answer:**
In synchronous communication, one service sends a request and waits for the response before continuing.

---

## Q8. What is asynchronous communication?

**Answer:**
In asynchronous communication, one service sends a message and continues its work without waiting for an immediate response.

---

## Q9. What are the advantages of Microservices Architecture?

**Answer:**

- Independent development
- Independent deployment
- Easy scalability
- Better fault isolation
- Faster development
- Easier maintenance

---

## Q10. What are the disadvantages of Microservices Architecture?

**Answer:**

- More complex architecture
- Difficult debugging
- Network communication overhead
- Complex deployment
- Increased monitoring requirements

---

## Q11. What is load balancing?

**Answer:**
Load balancing distributes incoming requests across multiple servers or service instances to improve performance and availability.

---

## Q12. What is scalability in microservices?

**Answer:**
Scalability is the ability to increase the capacity of a service by adding more instances when demand increases.

---

## Q13. What is fault tolerance?

**Answer:**
Fault tolerance is the ability of the system to continue functioning even if one or more services fail.

---

## Q14. Why is monitoring important in microservices?

**Answer:**
Monitoring helps track service health, performance, response time, resource usage, and errors, allowing issues to be detected and resolved quickly.

---

**Answer:**

- Design each service for a single business function.
- Keep services loosely coupled.
- Use a separate database for each service.
- Use an API Gateway.
- Secure APIs with authentication and authorization.
- Monitor and log all services.
