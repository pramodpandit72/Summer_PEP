# Docker, Containers, and CI/CD Basics

---

# What is Docker?

Docker is an open-source platform used to build, package, and run applications inside **containers**.

It ensures that an application runs the same way on every system, regardless of the operating system or environment.

Example:

A Node.js application developed on a laptop will run the same way on a server if both use Docker.

---

# Why Use Docker?

Without Docker:

- Applications may work on one computer but fail on another.
- Different software versions can cause compatibility issues.
- Deployment becomes difficult.

With Docker:

- Same environment everywhere
- Easy deployment
- Fast application startup
- Better resource utilization

---

# What is a Container?

A container is a lightweight, isolated environment that contains:

- Application code
- Runtime
- Libraries
- Dependencies
- Configuration files

A container shares the host operating system's kernel but runs independently.

# Docker Architecture

Docker consists of three main components.

## 1. Docker Client

The Docker Client is the command-line interface (CLI) used to interact with Docker.

Example:

```bash
docker run nginx
```

---

## 2. Docker Daemon

The Docker Daemon (`dockerd`) is a background service that:

- Builds images
- Creates containers
- Starts and stops containers
- Manages Docker resources

---

## 3. Docker Registry

A Docker Registry stores Docker images.

Popular Registries:

- Docker Hub
- GitHub Container Registry
- Amazon Elastic Container Registry (ECR)

---

# What is a Docker Image?

A Docker Image is a read-only template used to create containers.

It contains:

- Application code
- Required libraries
- Dependencies
- Runtime environment

Example:

```
Node.js Image
      |
Create Container
      |
Running Application
```

---

# Docker Image vs Container

| Docker Image | Docker Container |
|--------------|------------------|
| Blueprint or template | Running instance of an image |
| Read-only | Read and write |
| Used to create containers | Executes the application |
| Can create multiple containers | Runs one application instance |

---

# What is a Dockerfile?

A Dockerfile is a text file containing instructions to build a Docker image.

Example:

```dockerfile
FROM node:20

WORKDIR /app

COPY . .

RUN npm install

CMD ["npm", "start"]
```

Explanation:

- `FROM` → Base image
- `WORKDIR` → Working directory
- `COPY` → Copies project files
- `RUN` → Executes commands during image build
- `CMD` → Starts the application

# Common Docker Commands

## Pull an Image

```bash
docker pull nginx
```

Downloads an image from Docker Hub.

---

## List Images

```bash
docker images
```

Shows all downloaded images.

---

## Run a Container

```bash
docker run nginx
```

Creates and starts a container.

---

## List Running Containers

```bash
docker ps
```

Shows currently running containers.

---

## List All Containers

```bash
docker ps -a
```

Shows running and stopped containers.

---

## Stop a Container

```bash
docker stop <container-id>
```

Stops a running container.

---

## Remove a Container

```bash
docker rm <container-id>
```

Deletes a container.

---

## Remove an Image

```bash
docker rmi <image-id>
```

Deletes a Docker image.

# What is Virtualization?

Virtualization creates multiple virtual machines (VMs) on one physical machine.

Each VM has its own operating system.

---

# Docker vs Virtual Machine

| Docker | Virtual Machine |
|---------|-----------------|
| Uses containers | Uses virtual machines |
| Shares host OS kernel | Each VM has its own OS |
| Lightweight | Heavy |
| Faster startup | Slower startup |
| Uses less memory | Uses more memory |

# What is CI/CD?

CI/CD stands for:

- **CI** → Continuous Integration
- **CD** → Continuous Delivery / Continuous Deployment

It automates building, testing, and deploying applications.

---

# Continuous Integration (CI)

Continuous Integration is the practice of frequently merging code into a shared repository.

Every code change is automatically:

- Built
- Tested
- Verified

This helps detect errors early.

---

# Continuous Delivery (CD)

Continuous Delivery automatically prepares applications for deployment.

The deployment to production usually requires manual approval.

---

# Continuous Deployment

Continuous Deployment automatically releases every successful change to production without manual approval.

---

# Stages of a CI/CD Pipeline

## 1. Code

Developers write code.

---

## 2. Build

The application is compiled or packaged.

---

## 3. Test

Automated tests verify the application.

---

## 4. Package

The application is packaged, often as a Docker image.

---

## 5. Deploy

The application is deployed to a server or cloud environment.

---

## 6. Monitor

The deployed application is monitored for errors and performance.

# Best Practices

## Docker

- Use official base images.
- Keep images small.
- Use `.dockerignore` to exclude unnecessary files.
- Avoid storing sensitive information inside images.
- Build one application per container.

---

## CI/CD

- Automate builds and tests.
- Run tests before deployment.
- Keep pipelines simple.
- Monitor deployments.
- Roll back quickly if deployment fails.
