# System Design for Scalable Applications

---

# What is System Design?

System Design is the process of planning and designing the architecture of a software application.

It defines how different components work together to build a reliable, scalable, and efficient system.

Examples of large-scale systems:

- YouTube
- Instagram
- Amazon
- WhatsApp
- Netflix

---

# What is Scalability?

Scalability is the ability of a system to handle increasing numbers of users, requests, or data without losing performance.

A scalable system continues to work efficiently as traffic grows.

---

# Why is Scalability Important?

Without scalability:

- The application becomes slow.
- Servers may crash during high traffic.
- Users experience delays and errors.

With scalability:

- More users can access the application.
- Performance remains stable.
- Resources are used efficiently.

---

# Types of Scaling

## 1. Vertical Scaling (Scale Up)

Vertical scaling means increasing the resources of a single server.

Examples:

- More CPU
- More RAM
- More Storage

```
Before

Server
CPU: 2 Core
RAM: 4 GB

↓

After

Server
CPU: 8 Core
RAM: 32 GB
```

### Advantages

- Easy to implement
- No major changes to the application

### Disadvantages

- Limited by hardware capacity
- Expensive
- Single point of failure

---

## 2. Horizontal Scaling (Scale Out)

Horizontal scaling means adding more servers instead of upgrading one server.

```
Before

Client
   |
Server

↓

After

Client
   |
Load Balancer
   |
-------------------
|        |        |
Server1 Server2 Server3
```

### Advantages

- High availability
- Better fault tolerance
- Supports millions of users

### Disadvantages

- More complex architecture
- Requires load balancing

---

# Load Balancer

## What is a Load Balancer?

A Load Balancer distributes incoming requests across multiple servers.

This prevents one server from becoming overloaded.

---

## Load Balancer Architecture

```
Client
   |
Load Balancer
   |
-------------------------
|          |           |
Server1  Server2   Server3
```

---

## Benefits of Load Balancing

- Better performance
- High availability
- Fault tolerance
- Efficient resource utilization

---

# Caching

## What is Caching?

Caching stores frequently accessed data in memory so it can be retrieved quickly.

Instead of querying the database every time, the application first checks the cache.

Common caching tool:

- Redis

---

## Caching Flow

```
Client
   |
Application
   |
Redis Cache
   |
------------------------
|                      |
Cache Hit         Cache Miss
|                      |
Return Data      Database
                     |
               Store in Cache
```

---

## Benefits of Caching

- Faster response time
- Reduced database load
- Better user experience

---

# Database Scaling

As applications grow, a single database may not be enough.

There are two common techniques.

---

## 1. Replication

Replication creates copies of the database.

```
Primary Database
      |
-----------------------
|                     |
Replica 1        Replica 2
```

Primary:

- Handles write operations

Replicas:

- Handle read operations

Benefits:

- Faster reads
- Backup copies
- High availability

---

## 2. Sharding

Sharding divides data across multiple databases.

Example:

```
Shard 1

Users A-H

Shard 2

Users I-P

Shard 3

Users Q-Z
```

Benefits:

- Handles very large datasets
- Improves performance
- Supports horizontal scaling

---

# Content Delivery Network (CDN)

## What is a CDN?

A Content Delivery Network (CDN) is a group of servers located in different geographic locations.

It stores copies of static content close to users.

Examples of static content:

- Images
- Videos
- CSS files
- JavaScript files

---

## CDN Flow

```
User
   |
Nearest CDN Server
   |
Static Content
```

Benefits:

- Faster loading
- Reduced server load
- Better global performance

---

# Stateless Architecture

A stateless server does not store client information between requests.

Each request contains all the information required to process it.

Example:

JWT Authentication

Benefits:

- Easy scaling
- Better reliability
- Suitable for load balancing

---

# Microservices

Microservices divide an application into small independent services.

Example:

```
User Service

Order Service

Payment Service

Notification Service
```

Each service can be deployed and scaled independently.

---

# API Gateway

An API Gateway acts as the single entry point for all client requests.

Responsibilities:

- Request routing
- Authentication
- Authorization
- Rate limiting
- Logging

---

# Message Queue

Message Queues enable asynchronous communication between services.

Popular tools:

- RabbitMQ
- Apache Kafka

Example:

```
Order Service
      |
Message Queue
      |
Notification Service
```

Benefits:

- Loose coupling
- Background processing
- Better scalability

---

# Fault Tolerance

Fault tolerance means the system continues working even if one component fails.

Example:

If the Notification Service stops working:

- Orders continue.
- Payments continue.

Only notifications fail.

---

# High Availability

High Availability ensures that the application remains accessible even if a server fails.

Example:

```
Load Balancer
      |
-------------------
|        |        |
Server1 Server2 Server3
```

If one server fails, requests are sent to the remaining servers.

---

# Monitoring

Monitoring tracks the health and performance of the application.

Common metrics:

- CPU usage
- Memory usage
- Response time
- Error rate
- Server health

Popular tools:

- Prometheus
- Grafana

---

# Logging

Logging records application events.

Logs help with:

- Debugging
- Error tracking
- Security auditing
- Performance analysis

---

# Security

Scalable applications should implement proper security.

Common practices:

- HTTPS
- JWT Authentication
- OAuth 2.0
- Role-Based Access Control (RBAC)
- Input validation
- Rate limiting

---

# Best Practices

- Design stateless services.
- Use horizontal scaling.
- Implement caching with Redis.
- Use a CDN for static content.
- Apply database replication and sharding.
- Secure APIs with JWT or OAuth.
- Monitor system performance continuously.
- Use load balancing for high availability.
- Use message queues for background tasks.
- Log important events for troubleshooting.

# Important Questions with Answers

## Q1. What is System Design?

**Answer:**
System Design is the process of designing the architecture and components of a software application to ensure it is scalable, reliable, and efficient.

---

## Q2. What is scalability?

**Answer:**
Scalability is the ability of a system to handle increasing users, requests, or data while maintaining good performance.

---

## Q3. What is the difference between vertical and horizontal scaling?

**Answer:**

- Vertical scaling increases the resources (CPU, RAM, etc.) of a single server.
- Horizontal scaling adds more servers to distribute the workload.

---

## Q4. What is a Load Balancer?

**Answer:**
A Load Balancer distributes incoming requests across multiple servers to improve performance, availability, and fault tolerance.

---

## Q5. Why is caching used in scalable applications?

**Answer:**
Caching stores frequently accessed data in memory, reducing database load and improving response time.

---

## Q6. What is database replication?

**Answer:**
Database replication creates copies of a database. The primary database handles writes, while replicas handle read requests.

---

## Q7. What is database sharding?

**Answer:**
Database sharding divides data across multiple databases (shards) to improve performance and support large datasets.

---

## Q8. What is a CDN?

**Answer:**
A Content Delivery Network (CDN) is a network of servers that stores and delivers static content from locations closest to users.

---

## Q9. What is a stateless architecture?

**Answer:**
A stateless architecture does not store client information between requests. Each request contains all the information required for processing.

---

## Q10. What is the role of an API Gateway?

**Answer:**
An API Gateway acts as the single entry point for client requests and handles routing, authentication, authorization, and rate limiting.

---

## Q11. Why are message queues used in scalable systems?

**Answer:**
Message queues enable asynchronous communication, reduce service dependency, and improve scalability and reliability.

---

## Q12. What is fault tolerance?

**Answer:**
Fault tolerance is the ability of a system to continue operating even when one or more components fail.

---

## Q13. What is high availability?

**Answer:**
High availability ensures that the application remains accessible by using multiple servers and load balancing to handle failures.

---

## Q14. Why are monitoring and logging important?

**Answer:**
Monitoring tracks system performance and health, while logging records events for debugging, troubleshooting, and security analysis.

---

## Q15. What are the best practices for designing scalable applications?

**Answer:**

- Use horizontal scaling.
- Implement load balancing.
- Cache frequently accessed data with Redis.
- Use a CDN for static content.
- Apply database replication and sharding.
- Design stateless services.
- Use API Gateways and Microservices.
- Process background tasks with message queues.
