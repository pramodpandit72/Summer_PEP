# 1. What is Dynamic Programming?

## Definition

Dynamic Programming (DP) is an optimization technique used when a problem has:

- **Overlapping Subproblems**
- **Optimal Substructure**

Instead of solving the same subproblem multiple times, DP stores the answer and reuses it.

---

## Example

Find the 6th Fibonacci number.

Recursive approach

```
fib(6)

├── fib(5)
│   ├── fib(4)
│   └── fib(3)
└── fib(4)
```

Notice

```
fib(4)
```

is calculated multiple times.

DP stores it once.

---

## Why Use DP?

Without DP

```
Repeated Calculations
```

With DP

```
Reuse Previous Answers
```

# 2. When to Use DP?

A problem is a good candidate for DP if:

### 1. Overlapping Subproblems

Same problem is solved repeatedly.

Example

```
Fibonacci
```

---

### 2. Optimal Substructure

The optimal solution can be built from optimal solutions of smaller problems.

Example

```
Shortest Path
```

```
Knapsack
```

```
Longest Increasing Subsequence
```

# 3. DP Terminology

## State

The information needed to uniquely define a subproblem.

Example

```
dp[i]
```

Meaning

```
Answer for first i elements
```

---

## Transition

How one state depends on previous states.

Example

```
dp[i] = dp[i-1] + dp[i-2]
```

---

## Base Case

The smallest problem whose answer is already known.

Example

```
dp[0] = 0

dp[1] = 1
```

---

## DP Array

Stores answers to subproblems.

Example

```cpp
vector<int> dp(n + 1);
```

# 5. Memoization (Top-Down)

Uses

- Recursion
- DP Array

---

Example

```cpp
int fib(int n, vector<int>& dp)
{
    if(n <= 1)
        return n;

    if(dp[n] != -1)
        return dp[n];

    return dp[n] = fib(n - 1, dp) + fib(n - 2, dp);
}
```

---

## Complexity

Time

```
O(N)
```

Space

```
O(N)
```

---

## Advantages

- Easy to write.
- Natural recursive thinking.

---

## Disadvantages

- Uses recursion stack.
- Stack overflow for very large inputs.

---

# 6. Tabulation (Bottom-Up)

Uses iteration.

---

Example

```cpp
int fib(int n)
{
    if(n <= 1)
        return n;

    vector<int> dp(n + 1);

    dp[0] = 0;
    dp[1] = 1;

    for(int i = 2; i <= n; i++)
        dp[i] = dp[i - 1] + dp[i - 2];

    return dp[n];
}
```

---

## Complexity

Time

```
O(N)
```

Space

```
O(N)
```

---

## Advantages

- No recursion.
- Faster in practice.

---

# Memoization vs Tabulation

| Feature | Memoization | Tabulation |
|----------|-------------|------------|
| Approach | Top-Down | Bottom-Up |
| Uses Recursion | Yes | No |
| Stack Space | Yes | No |
| Easy to Write | Yes | Moderate |
| Preferred in Interviews | Both | Often Tabulation |

# 7. Space Optimization

Many DP problems only need previous states.

Example

```
dp[i]

depends only on

dp[i-1]

dp[i-2]
```

Instead of an array,

use two variables.

---

Example

```cpp
int fib(int n)
{
    if(n <= 1)
        return n;

    int prev2 = 0;
    int prev1 = 1;

    for(int i = 2; i <= n; i++)
    {
        int curr = prev1 + prev2;

        prev2 = prev1;
        prev1 = curr;
    }

    return prev1;
}
```

---

Complexity

Time

```
O(N)
```

Space

```
O(1)
```

# DP Thinking Strategy

Whenever you see a problem, ask:

1. What is the state?
2. What choices do I have?
3. What is the recurrence?
4. What are the base cases?
5. Can I optimize space?

# 10. Common Mistakes

## Forgetting Base Cases

Most DP bugs come from incorrect base cases.

---

## Wrong State Definition

If your state is incorrect,

everything becomes difficult.

---

## Not Memoizing

Pure recursion often causes

```
TLE
```

---

## Wrong Loop Order

Tabulation depends on previous states.

Compute them first.

---

## Missing Space Optimization

Always check if only a few previous states are required.
