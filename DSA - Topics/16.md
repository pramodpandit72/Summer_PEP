# 1. Introduction to Greedy Algorithms

## What is a Greedy Algorithm?

A **Greedy Algorithm** makes the **best possible choice at the current step** without worrying about future consequences.

The hope is that these local optimal choices lead to a globally optimal solution.

---

## Example

Suppose you have coins

```
1 2 5
```

To make

```
11
```

Greedy chooses

```
5

5

1
```

Total coins

```
3
```

---

## Another Example

Activity Scheduling

```
Activity

Start End

1      2

3      4

0      6

5      7
```

Always choose the activity that finishes earliest.

---

# Key Idea

```
Make the best decision now.
```

No reconsideration later.

---

# 2. Greedy vs Dynamic Programming

| Greedy | Dynamic Programming |
|----------|--------------------|
| Makes local optimal choice | Explores all possibilities |
| Faster | Usually slower |
| Less memory | More memory |
| Not always correct | Gives optimal answer if DP applies |
| Easier to implement | More complex |

---

Example

Coin denominations

```
1 3 4
```

Amount

```
6
```

Greedy

```
4 + 1 + 1

=

3 coins
```

Optimal

```
3 + 3

=

2 coins
```

Greedy fails.

DP succeeds.

# 3. When to Use Greedy?

Greedy usually works if the problem has

### Greedy Choice Property

Making the locally best choice eventually leads to the optimal answer.

---

### Optimal Substructure

Optimal solution can be built from optimal solutions of subproblems.

---

Common clues

- Minimum number
- Maximum profit
- Earliest finish
- Smallest/Largest value first
- Sort first
- Interval scheduling
- Merge intervals

---

# 4. How to Prove a Greedy Algorithm?

Interviewers may ask:

> Why does your greedy solution work?

You should explain:

### Greedy Choice Property

The first choice is always safe.

---

### Exchange Argument

Show that if another optimal solution exists,

you can exchange its first choice with your greedy choice

without making the answer worse.

---

### Optimal Substructure

After making the greedy choice,

the remaining problem is solved optimally.

# 6. Classic Greedy Algorithms

---

## Activity Selection

Choose activities with

```
Smallest Ending Time
```

Complexity

```
O(N log N)
```

---

## Fractional Knapsack

Sort by

```
Value / Weight
```

Take as much as possible.

Complexity

```
O(N log N)
```

---

## Huffman Coding

Always merge

```
Two smallest frequencies.
```

Uses

```
Min Heap
```

---

## Job Sequencing

Sort by

```
Profit
```

Schedule jobs before deadlines.

---

## Kruskal's MST

Sort edges by

```
Weight
```

Uses

```
DSU
```

---

## Prim's MST

Always choose

```
Minimum Edge
```

Uses

```
Priority Queue
```

# 8. Common Mistakes

## Assuming Greedy Always Works

Many optimization problems require DP instead.

---

## Forgetting to Sort

Most interval-based greedy solutions require sorting first.

---

## Choosing Wrong Sorting Order

Sometimes sort by

- Start time
- End time
- Profit
- Ratio

Choosing the wrong criterion gives incorrect answers.

---

## Ignoring Edge Cases

Examples

- Empty array
- Single interval
- Duplicate values

---

## Confusing Greedy with Backtracking

Greedy never revisits previous decisions.

Backtracking does.
